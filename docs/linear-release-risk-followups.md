# Release Risk Follow-Ups

_Last reviewed 2026-10-30._ An August release review raised six risks to track before a network-visible deployment. They were meant to become Linear issues; the production launch plan picked them up instead. All six are now resolved. What is left of them is tracked as launch items, named below.

| # | Risk (priority) | Status | Where it was resolved |
|---|---|---|---|
| 1 | Provider-backed API routes callable without sign-in, tenancy or rate limits (High) | **Resolved** | Every route needs a session, except the public health routes, the cron routes (their secret) and the Plaid webhook (Plaid's signature). Routes take the user from the session alone (`requireSessionApiUserScope`), and Plaid records are per user. Alpha Radar changes and refreshes are admin-only (launch item i69). Limits are per IP and per user in Upstash, and errors are generic codes. See `docs/SECURITY-AUDIT.md`. |
| 2 | Plaid tokens not durable, user-scoped or reconnectable (High) | **Resolved** | Production stores tokens in Postgres (`plaid_items`), encrypted with `PLAID_TOKEN_ENCRYPTION_KEY`, which it refuses to replace with any other secret. Each connection has a status and its last successful sync. A connection that needs a sign-in reconnects through Link's update mode; Plaid's webhooks report new data, sign-in needed, consent ending and revocation; Disconnect removes the item at Plaid and here. The encrypted file vault is for local development only. |
| 3 | Unbounded Alpha Radar inputs; 13F information tables filed as attachments missed (Medium) | **Resolved** | Inputs are validated with explicit limits (`src/lib/validators/alpha-radar.ts`) and request bodies are capped (413). SEC requests have timeouts and response-size limits (`src/lib/sec/fetch-limits.ts`). Discovery looks for an information table in the filing's attachments, not only the primary document (`findInformationTableAttachment`, tested in `edgar-client.test.ts`). Optional embeddings remain launch item i62. |
| 4 | Drizzle migration metadata missing a snapshot; generated files in the tree (Medium) | **Resolved** | `drizzle/meta` has a snapshot for every migration (0000–0025), and the journal matches the SQL files. Playwright reports and test results are ignored. CI applies every migration to a fresh database on each pull request. |
| 5 | `npm run lint` failing repo-wide (High) | **Resolved** | Lint is clean and gates `lint-and-test` on every pull request. |
| 6 | CSP allowing inline and eval scripts; CI actions pinned by tag (Medium) | **Resolved** | Every response has a nonce-based policy with `'strict-dynamic'`: no `'unsafe-inline'` for scripts, and `'unsafe-eval'` only in development. Plaid's script, frame and API origins are listed explicitly (launch item i26; `content-security-policy.spec.ts`). Every workflow action is pinned to a commit SHA, with permissions set per job. |
